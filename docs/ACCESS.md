# Доступ до додатку: вхід, пробний період, коди

## Як це працює для користувача

1. При запуску додаток показує екран **входу** (пошта + пароль). Новий
   користувач реєструється і отримує лист для підтвердження пошти; поки
   пошту не підтверджено, далі не пускає.
2. Після входу додаток визначає **тип доступу**:

| Хто | Доступ |
|---|---|
| Пошта на корпоративному домені (`@forestcollege.ukr.education`) | безкоштовно, без обмежень |
| Усі інші | безкоштовно **30 днів** від першого входу, далі — потрібен код |
| Хто ввів **код доступу** від адміністратора | назавжди або на стільки днів, скільки задано в коді |

3. Коли пробний період добігає кінця, під банером з'являється смужка
   «Пробний період: залишилось N дн. — Ввести код». Після завершення —
   екран «Пробний період завершився» з полем для коду.
4. Іконка **акаунта** (👤 у верхньому правому куті) показує пошту, стан
   доступу, дає ввести код, змінити пароль або вийти.

Пробний період прив'язаний до **акаунта, а не до пристрою**: дата першого
входу записується серверним часом Firestore, тож перевстановлення додатку
або переведення годинника нічого не скидає.

## Адміністратору: коди доступу

Адмін-панель → **Коди доступу**.

- **Створити код** — генерується 8-символьний код (без схожих символів
  0/O/1/I). Параметри:
  - *Кількість активацій* — скільком користувачам він підійде (або «Без ліміту»);
  - *Доступ на … днів* — або «Назавжди»;
  - *Термін* — до якої дати код узагалі можна активувати (необов'язково);
  - *Примітка* — кому/для чого виданий.
- Кожен код показує, скільки разів і **ким** (пошта) його активовано.
- **Деактивувати** — код більше не приймається; ті, хто вже активував,
  доступ не втрачають. **Видалити** — те саме, але назавжди.
- ⚙ у шапці — **налаштування**: список корпоративних доменів, тривалість
  пробного періоду (днів), пошти адміністраторів (кому правила Firestore
  дозволяють керувати кодами). Той, хто зберігає, автоматично лишається в
  списку адміністраторів.

Вхід в адмін-панель, як і раніше, — за локальним паролем; але сам адмін
теж має бути залогінений у додаток своєю поштою (для правил Firestore).

## Одноразове налаштування Firebase

1. **Authentication → Sign-in method → Email/Password** — увімкнути
   (станом на 22.09.2026 вже увімкнено).
2. **Правила Firestore** (`firestore.rules` у корені репозиторію):

       firebase login
       firebase deploy --only firestore:rules

   Без цього кроку додаток працює, але `users`/`access_codes` лишаються
   відкритими на запис, і технічно підкований користувач може подовжити
   собі пробний період. Правила залишають решту колекцій відкритими, як
   вони є зараз (сайт пише в них без Auth).
3. Увійти в додаток корпоративною поштою, відкрити Адмін-панель → Коди
   доступу → ⚙ → **Зберегти налаштування**. Це створює документ
   `app_access/config` із вашою поштою як адміністратора.
4. **Authentication → Settings → Authorized domains** — додати
   `lisovi-surmy-site.vercel.app` і `lisovi-surmy.vercel.app`.
5. (Необов'язково) **Authentication → Templates** — українізувати текст
   листа підтвердження пошти.

## Структура даних

    app_access/config       { corporateDomains: [..], trialDays: 30, adminEmails: [..] }
    users/{uid}             { email, createdAt, lastSeenAt, accessType: 'trial'|'code',
                              codeId?, codeActivatedAt?, accessUntil? (null = назавжди) }
    access_codes/{CODE}     { note, maxUses (0 = ∞), usedCount, usedBy: [uid], usedByEmails,
                              durationDays (null = назавжди), expiresAt?, active, createdAt }

Код: `lib/services/access_service.dart` (логіка), `lib/widgets/access_gate.dart`
(перемикач екранів), `lib/screens/auth_screen.dart`, `verify_email_screen.dart`,
`access_expired_screen.dart`, `account_screen.dart`, `admin_access_screen.dart`.

## Сайт

Сайт (`site/`, lisovi-surmy-site.vercel.app) працює за тими самими правилами
і з тими самими даними: `site/js/access.js` (логіка), `site/js/views/access.js`
(вхід, підтвердження, акаунт, смужка), `site/js/views/admin-access.js`
(коди й налаштування в адмін-панелі). Акаунт, пробний період і коди спільні
для додатку й сайту — користувач входить однією поштою будь-де.

Після деплою сайту додайте його домен у **Authentication → Settings →
Authorized domains** (`lisovi-surmy-site.vercel.app`; `localhost` там є
за замовчуванням).

## Що не покрито

- Оплата після пробного періоду не реалізована — лише коди від адміністратора.
- Вхід через Google не додано: у `google-services.json` немає справжнього
  SHA-1 підпису застосунку; за потреби додається окремо.
